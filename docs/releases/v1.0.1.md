# OIE Web Client 1.0.1

OIE Web Client 1.0.1 fixes import behavior in Web Administrator for OIE 4.6.0.

## Changes since 1.0.0

- Load multiple code-template libraries and merge library imports while retaining
  unrelated libraries and templates. Resolve matching items with overwrite,
  import-as-copy, and keep-existing choices.
- Preserve channel and group identities, memberships, bundled library bindings,
  dependencies, and resource mappings during imports. Channel imports use the
  engine clock and share the editor's last-saver check and overwrite confirmation
  when the engine reports a conflict.
- Accept Swing connector, filter, and transformer exports, including destination
  imports with fresh identities and transformer append/replace/cancel choices.
- Align configuration-map replacement and properties-file handling with Swing,
  and validate alert names and import conflict decisions.
- Import messages from local files and folders, server paths, ZIP, TAR, TAR/GZip,
  and TAR/BZip2 archives, with recursion and partial-result reporting.

## Compatibility and limitations

The supported engine remains OIE 4.6.0. Existing Node, Docker, and WAR deployment
options remain available, with Node.js 22.18.0 or newer required for Node builds.

Imports can retain completed writes when a later stage fails or is cancelled.
Exports using the older rule or step XML format require re-export through Swing.
The separate engine XML-to-JSON character-encoding defect is not fixed by this
web-client release.
