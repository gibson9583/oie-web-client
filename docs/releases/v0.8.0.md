# OIE Web Client 0.8.0

OIE Web Client 0.8.0 is the refinement baseline for the OIE 4.6 release line.
It strengthens channel lifecycle, import/export, message handling, and code-template
workflows, and adds locally hosted fonts with per-user UI and data-font choices.

## Highlights since 0.7.0

- Added bulk channel lifecycle operations and corresponding audit records.
- Made code-template saves atomic and dependency-aware.
- Preserved channel groups, channel dependencies, attachments, metadata, and usable
  backups across import/export workflows; alert imports now resolve conflicts safely.
- Protected PHI-sensitive message operations with audit coverage and made removal
  from running channels explicit.
- Surfaced secondary-load failures instead of silently rendering incomplete views.
- Replaced network-loaded fonts with bundled assets. Inter and JetBrains Mono are
  the defaults, with per-user UI/data font preferences and a working live reset.
- Kept WAR packaging isolated from the Node/Docker build output so creating a WAR
  cannot break nested routes in a subsequent standalone deployment.

## Compatibility

- Open Integration Engine 4.6.0 is the supported and smoke-tested engine version.
  Earlier engine releases are not supported by this release line.
- OIE Web Support is required for byte-exact message-tree serialization, script
  validation and formatting, engine-served plugin UIs, and its embedded WAR
  deployment. Local validation used plugin version 0.1.1 declaring OIE 4.6.0.
- **Release gate:** there is no identified published Web Support artifact for this
  pairing. The available companion source release is 1.0.1, targets OIE 4.5.2,
  and embeds web client 0.7.0; installing it can replace the 0.8.0 WAR with 0.7.0.
  The `v0.8.0` Git tag and all artifact publication remain deferred until Web
  Support publishes an OIE 4.6-compatible build embedding web client 0.8.0.
- Node 22 LTS is recommended; Node 20.19 or newer is the minimum build runtime.
- Third-party web plugins may declare `oie.apiMin`. Version 0.8.0 exposes the 4.6.0
  web API contract and will refuse to execute plugins requiring a newer contract.

## Upgrade

These steps apply only after the Web Support release gate above is cleared and its
release manifest names the exact compatible extension build.

1. Back up the current WAR/image or record the currently pinned Node revision and
   configuration. Back up OIE through its normal server-administration process.
2. Install that exact OIE 4.6-compatible Web Support package, then restart OIE.
3. Choose one deployment:
   - Node: check out `v0.8.0`, run `npm ci`, build the web administrator, and restart
     the Node service with the existing configuration.
   - Docker: replace the pinned image with `gibson9583/oie-web-client:0.8.0` and
     recreate the container with the same environment variables and mounts.
   - WAR: copy `oie-webadmin.war` into `<OIE_HOME>/webapps/` and restart OIE.
4. Sign in and verify a representative read plus a disposable, undeployed channel
   create/delete before returning the deployment to service.

No web-client data or database migration is required. Browser preferences already
stored by 0.7.0 are retained; the new font preferences use defaults until changed.

## Rollback

Stop the selected web-client deployment, restore the previously backed-up WAR or
Node revision (or recreate the container with its previous immutable image tag),
and restart it with the unchanged configuration.

To roll back Web Support, uninstall it through Extensions and restart OIE; that
restart removes its deployed `webapps/oie-webadmin.war`. Install the backed-up
previous Web Support ZIP through the Swing Administrator and restart again. If OIE
was force-killed while uninstall was pending, delete the deployed WAR before
installing the prior ZIP. No web-client database downgrade is necessary.

## Known limitations

- WAR mode is intentionally single-engine and does not provide Node-managed TLS,
  extra local `pluginDirs`, confidential-client OIDC, or user-entered engine URLs.
  Use Node or Docker when those features are required.
- Docker and standalone Node serve plain HTTP by default. Terminate TLS upstream or
  configure the Node TLS settings before exposing either deployment to a network.
- Features supplied by Web Support are disabled when the compatible extension is
  absent; the rest of the administrator remains available.

## Local release validation

The 0.8.0 candidate passed lint, type checking, unit tests, the mocked Playwright
suite, WAR assembly validation, and login plus disposable channel CRUD against a
real OIE 4.6.0 engine through Node, Docker, and WAR deployments.

- Expected immutable Docker tag: `gibson9583/oie-web-client:0.8.0`
- Expected convenience Docker tags: `gibson9583/oie-web-client:0.8` and `latest`

This release was prepared under a local-only constraint. The authoritative WAR
SHA-256 must be generated beside the exact immutable asset after the Web Support
gate is cleared; a checksum committed before that rebuild would be stale because
WAR entry timestamps change on every assembly. The Git tag is deliberately absent.
WAR publication/checksum verification, Docker tag publication/digest verification,
remote Git tag publication, and hosted release creation are deferred to an explicitly
authorized publishing session after a compatible Web Support artifact exists.
